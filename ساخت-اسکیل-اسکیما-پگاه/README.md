# ساخت-اسکیل-اسکیما-پگاه

از یک اسکیمای دیتابیس، **سند دانش** و **اسکیل تسلط** می‌سازد. در فرمت
استاندارد `SKILL.md`. مستقل است: این پوشه را هرجا بگذاری کار می‌کند.

```
SKILL.md                        دستورالعمل — چیزی که مدل هر بار می‌خواند
scripts/build_map.py            درون‌نگری → schema.json + findings.md
scripts/scaffold.py             schema.json → سند دانش + پوشه‌ی اسکیل
scripts/crosslink.py            چند schema.json → cc_resolution + skills-index.json
templates/map.py                اسکریپت پیمایش که در هر اسکیل کپی می‌شود
references/introspection.md     SQL درون‌نگری، تکه‌کردن، و اعتبارسنجی
references/conventions.md       زبانِ نام‌گذاری این خانواده دیتابیس
references/authoring.md         پر کردن TODOها و معیارِ تمام‌شدن
examples/humanresource-recipe.md همین کار روی HumanResource، با عددهای واقعی
```

## چه می‌سازد

برای هر اسکیما دو چیز:

۱. **`<Schema> Map.md`** — سند دانش: قاعده‌های تفسیر، نقشه‌ی دامنه، دستگاه
   `cc`، فرهنگ جدول‌ها، فهرست اتصال‌ها، تله‌ها.
۲. **پوشه‌ی اسکیل** — `SKILL.md`، `schema.json`، `scripts/map.py`، چهار
   `references/`، و `examples/` — کنارِ بقیه‌ی اسکیل‌ها.

و بعدش گامِ سوم که فراموش‌شدنی است: `crosslink.py` اسکیلِ تازه را به بقیه
وصل می‌کند. بدون آن، ارجاع‌های بین‌اسکیمایی «حل‌نشده» می‌مانند.

## خط لوله

```bash
# ۱. درون‌نگری (references/introspection.md) → raw/
# ۲. نقشه
python scripts/build_map.py raw/ --schema Sales --out schema.json

# ۳. findings.md را بخوان، domains.json بنویس، دوباره بساز
python scripts/build_map.py raw/ --schema Sales --domains domains.json --out schema.json

# ۴. اعتبارسنجی (بخش ۹ introspection.md) — آزمونِ یتیم روی یال‌های پرکاربرد

# ۵. خروجی‌ها
python scripts/scaffold.py readme schema.json --out "Sales Map.md"
python scripts/scaffold.py skill  schema.json --out ../تسلط-فروش-پگاه --name تسلط-فروش-پگاه

# ۶. همه‌ی <!-- TODO --> ها را پر کن (references/authoring.md)
```

پایتون ۳.۹ به بالا، بدون وابستگی بیرونی.

## ماشین چه می‌کند

خودکار و قابل اعتماد:

- فهرست جدول/ستون/نوع، کلید اصلی اعلام‌شده و حدسی
- یال‌های `ccX` با قاعده‌ی `A.ccB → B`، و ادغام کلیدهای خارجی واقعی
- طبقه‌بندی: بازه‌دار، وضعیت‌دار، سطر، دفتر، دیکشنری، درختی، میراث، مهاجرت،
  محرمانه، خالی
- **تشخیص تله:** جدول دوقلو (نرمال‌سازیِ `i↔y`, `o↔u`, حذف واکه)، سطری که
  پدرش آنی نیست که اسمش می‌گوید، ناسازگاری نوع و عرض، ستون مرده،
  `BeginDate` به‌جای `FromDate`، `EndDate` تهی‌ناپذیر
- تفکیک شواهد: `DECLARED_FK/CONFIRMED` تا `NAMING_ONLY/LOW`

## آدم چه می‌کند

بدون اینها اسکیل فقط `schema.json` است با ظاهرِ مارک‌داون:

- نام و مرزِ دامنه‌ها
- نقشِ هر جدول در یک جمله — با **دانه**، نه ترجمه‌ی اسم
- اینکه کدامِ دو جدولِ دوقلو مرجع است
- تفسیر ارجاع‌های بیرونی و پل‌های بین اسکیمایی
- قاعده‌های کسب‌وکاری، واحدِ مبالغ، جهتِ `BedBes`
- سؤال‌های بازِ «از کارشناس بپرس»
- نمونه‌ی کارِ کامل، و محرمانگی

## چرا این با مشخصاتِ `GenerateDomainReadme` فرق دارد

آن نسخه یک **طرحِ پرامپت** بود: ۱۶ فاز، طبقه‌بندی شواهد، و قالب README.
واژگانِ شواهد/اطمینانش اینجا هم به کار رفته. سه چیز اضافه شده:

- **ابزارِ اجرایی** به‌جای دستورالعملِ متنی — قابل تکرار و قابل تست.
- **تشخیص تله** که آن نسخه اصلاً نداشت، و همان‌ها بیشترین وقت را می‌گیرند.
- **محدودیت‌های میزبان**: سقف ۵۰۰ سطرِ `run_query` و ممنوعیت `DECLARE`.
  نقشه‌ای که ستون‌هایش نصفه جمع شده، بی‌صدا غلط است.

و خروجی دوم — **خودِ اسکیل** — که آن نسخه فقط README می‌ساخت.

## دو خطایی که اعتبارسنجی گرفت

هر دو با مقایسه با اسکیل‌های **تست‌شده‌ی فروش** پیدا شدند، نه با خواندن کد:

- **`AmarForosh_Arshive` میراث علامت خورده بود** چون `_Arshive` دارد — در
  حالی که مرکزِ کلِ گزارش‌های فروش است. حالا `archive_check` می‌گیرد یعنی
  «بشمار، بعد تصمیم بگیر». در این دیتابیس آرشیو گاهی خودِ جدولِ اصلی است.
- **همه‌ی جدول‌ها «خالی» علامت خورده بودند** چون فهرست ستون‌ها تعداد سطر
  ندارد و «نامعلوم» با «صفر» یکی گرفته شده بود. حالا `rows_unknown`.

هر دو از یک جنس‌اند: **ماشین نبودِ داده را با دانستنِ چیزی اشتباه گرفته
بود.** همان چیزی که اعتبارسنجی برای آن است.

## محدودیت‌های شناخته‌شده

- **دامنه‌بندی خودکار نیست** — خوشه‌ی پیشنهادی می‌دهد، نام‌گذاری با آدم است.
- **دوقلوی واژه‌متفاوت پیدا نمی‌شود** — فقط نویسه‌گردانی.
- **نقش‌ها خالی می‌مانند.** عمدی: نقشِ حدسی از نقشِ خالی بدتر است.
- **رابطه‌ی چندستونی** پشتیبانی نمی‌شود؛ قاعده‌ی `cc` تک‌ستونی است.
- **اعتبارسنجی خودکار نیست** — کوئری‌هایش آماده است، اجرا با عامل.

## پیوند با بقیه‌ی اسکیل‌ها

پنج اسکیل با این ساخته شده‌اند: `تسلط-مشترک-پگاه` (`Global`، ۱۱۹ جدول)،
`تسلط-فروش-پگاه` (`Sales`، ۴۳۵)، `تسلط-انبار-پگاه` (`Warehouse`، ۱۷۰)،
`تسلط-خزانه-پگاه` (`Treasury`، ۱۵۲) و `منابع-انسانی-پگاه`
(`HumanResource`، ۴۱۳).

`scripts/crosslink.py` گامِ بعدِ ساختِ هر نقشه است: چند `schema.json` را کنار
هم می‌گذارد و چیزی را حل می‌کند که هیچ‌کدام به‌تنهایی نمی‌توانند — ارجاعِ
نقش‌دار، ارجاعِ دوپهلو، غلط‌املای شناسه، و ارجاعِ واقعاً بی‌مقصد. روی این
خانواده ۲۶۴ ارجاعِ «بی‌مقصد» را به نامزد رساند.

**اسکیمای بعدی که نقشه می‌خواهد `FinancialAccounting` است** — بی آن،
`ccHesab0..7` در خزانه و `ccTafsily` در منابع انسانی قابلِ تفسیر نیستند.

نقشه‌ی کامل خانواده، ماتریسِ ارجاع و فهرستِ ارجاع‌های حل‌نشده در
[../SKILLS.md](../SKILLS.md). عددها را `crosslink.py` می‌سازد؛ دستی
به‌روزشان نکن.
