# یک سؤال واقعی، از اول تا آخر

**سؤال کاربر:** «مرداد ۱۴۰۵ کدام گروه کالا کمترین تحقق هدف را داشت؟»

سؤال کوتاه است ولی پنج تصمیم در آن پنهان است. مسیر زیر نشان می‌دهد کدام
تصمیم کجا گرفته می‌شود، و **چه چیزی پرسیده می‌شود و چه چیزی نه**.

---

## گام ۰ — تأیید، و اینجا از همیشه مهم‌تر است

```sql
-- کوئری ۰.۱ — آخرین تاریخِ داده در هر جدولِ نامزد
```

**چرا اول این:** سه جدول در این اسکیما اسمشان دقیقاً «هدف فروش» است و در
۲۰۱۸ ایستاده‌اند. اگر کوئری را روی `HadafForosh` بنویسی، جوابِ به‌ظاهر
معقولِ کاملاً غلط می‌گیری.

انتظار:

| جدول | وضعیت |
|---|---|
| `HadafForoshRoozanehNew` | **زنده — این را بگیر** |
| `HadafForoshRoozaneh` | ستون هدفش در ۱۴۰۵ صفر است |
| `HadafForosh` | مرده، ۲۰۱۸ |
| `AmalkardRozanehForosh` | مرده، ۲۰۱۸ |

## گام ۱ — «تحقق» یعنی چه

`HadafForoshRoozanehNew` **هدف و عملکرد را با هم دارد**، پس لازم نیست به
`AmarForosh_Arshive` وصل شوی. ولی سه واحد دارد:

| واحد | ستون‌ها |
|---|---|
| تعدادی | `TedadHadaf` / `TedadForosh` |
| ریالی | `RialHadaf` / `RialForosh` |
| وزنی | `VaznHadaf` / `VaznForosh` |

**پیش‌فرض تعدادی است** — همان چیزی که اسکیل ارزیابی فروشنده استفاده می‌کند.
این را **نپرس**؛ اعمال کن و در گزارش بنویس. (در یک مسیر واقعی تعدادی ۲۶۸٪
و ریالی ۱۷۶٪ درآمد — ۹۲ واحد اختلاف.)

## گام ۲ — تحققِ کل، نه میانگینِ درصدها

این تنها جایی است که خرابیِ خاموش دارد:

```
درست  :  Σ فروش ÷ Σ هدف
غلط   :  میانگینِ (فروشِ هر گروه ÷ هدفِ هر گروه)
```

میانگینِ درصدها با یک گروهِ ریزِ پرتحقق تا **۴۲۳٪** بالا می‌رود، چون گروهی
با هدف ۴ همان وزنی را دارد که گروهی با هدف ۱۳٬۴۵۴. سؤال «کمترین تحقق» است،
پس این خطا مستقیم جوابِ اشتباه می‌دهد.

## گام ۳ — بازه و لاین

- **بازه:** مرداد ۱۴۰۵ = میلادیِ معادلش. تاریخ‌ها `datetime` میلادی‌اند.
- **لاین فروش:** بپرس. مبناها برای لاین یک نوشته شده‌اند و اگر همه‌ی
  لاین‌ها با هم بیایند، مقایسه معنی‌اش عوض می‌شود. **این تنها سؤالِ
  متوقف‌کننده‌ی این مسیر است.**

## گام ۴ — نام گروه کالا

```
python scripts/map.py external | grep Goroh
```

`ccGorohKala` به `Global.Goroh` می‌رود با `ccGorohLink = 560` (۵۵ گروه).

> **`Global.vGorohMahsol` را نگیر** — فقط ۳۳ گروه از ۵۵ را دارد. کترینگ
> فروشگاهی، مربا لاویز، ترشیجات لاویز و چند تای دیگر در آن نیستند و
> **بی‌نام درمی‌آیند** — که در جدولِ «کمترین تحقق» یعنی سطرهای بی‌نام.

## گام ۵ — کوئری

```sql
WITH params AS (
    SELECT CAST('2026-07-23' AS date) AS az_tarikh,   -- ۱۴۰۵/۰۵/۰۱
           CAST('2026-08-22' AS date) AS ta_tarikh,   -- ۱۴۰۵/۰۵/۳۱
           1                          AS sazman_forosh
)
SELECT h.ccGorohKala,
       g.NameGoroh,
       SUM(h.TedadHadaf)   AS hadaf,
       SUM(h.TedadForosh)  AS forosh,
       CASE WHEN SUM(h.TedadHadaf) = 0 THEN NULL
            ELSE 100.0 * SUM(h.TedadForosh) / SUM(h.TedadHadaf)
       END                 AS darsad_tahaghogh,
       COUNT(DISTINCT h.ccForoshandeh) AS tedad_masir
FROM [Sales].[HadafForoshRoozanehNew] AS h
CROSS JOIN params AS p
LEFT JOIN [Global].[Goroh] AS g
       ON g.ccGoroh = h.ccGorohKala AND g.ccGorohLink = 560
WHERE h.Tarikh >= p.az_tarikh AND h.Tarikh <= p.ta_tarikh
GROUP BY h.ccGorohKala, g.NameGoroh
HAVING SUM(h.TedadHadaf) > 0
ORDER BY darsad_tahaghogh ASC;
```

سه چیز عمدی:

- **`HAVING SUM(TedadHadaf) > 0`** — گروهی که هدف ندارد تحقق ندارد، صفر
  درصد نیست. بدون این، صدر جدولِ «کمترین تحقق» پر از گروه‌های بی‌هدف
  می‌شود.
- **`SUM` قبل از تقسیم** — قاعده‌ی گام ۲.
- **`tedad_masir`** — گروهی که فقط یک مسیر فروخته، عددش نویز است نه سیگنال.

## گام ۶ — گزارش

```
کمترین تحقق هدف — مرداد ۱۴۰۵

بازه       : ۱۴۰۵/۰۵/۰۱ تا ۱۴۰۵/۰۵/۳۱ (۲۰۲۶-۰۷-۲۳ تا ۲۰۲۶-۰۸-۲۲)
لاین فروش  : لاین یک (ccSazmanForosh = 1)
واحد       : تعدادی (TedadHadaf / TedadForosh)
منبع       : Sales.HadafForoshRoozanehNew — هدف و عملکرد از همین جدول
روش        : Σفروش ÷ Σهدف به تفکیک گروه، نه میانگینِ درصدها
نام گروه   : Global.Goroh با ccGorohLink = 560

┌───┬──────────────────┬────────┬────────┬─────────┬───────┐
│ ۱ │ <گروه>           │ <هدف>  │ <فروش> │ <درصد>  │ <مسیر>│
└───┴──────────────────┴────────┴────────┴─────────┴───────┘

گروه‌های بدون هدف در بازه از جدول کنار گذاشته شدند (تحقق تعریف‌نشده است،
نه صفر). گروه‌هایی که فقط یک مسیر داشتند با ستون «مسیر» مشخص‌اند.

تأییدنشده: اتصال ccGorohKala به Global.Goroh از هم‌نامی است و کلید خارجی
ندارد؛ N گروه از M گروه نام گرفتند.
```

## چه پرسیده شد و چه پرسیده نشد

| پرسیده شد | چون |
|---|---|
| کدام لاین فروش | جمعیتِ مقایسه را عوض می‌کند و از داده حل نمی‌شود |

| پرسیده نشد | چون |
|---|---|
| واحد تعدادی یا ریالی | پیش‌فرضِ معقول دارد؛ در گزارش نوشته شد |
| کدام جدولِ هدف | با `MAX(Tarikh)` معلوم می‌شود، سؤال نیست |
| تحققِ کل یا میانگین | یکی از این دو **غلط** است؛ انتخاب نیست |
| نام گروه از کجا | `vGorohMahsol` ناقص است — تصمیمِ فنی، نه کسب‌وکاری |

**سؤالی که با یک کوئری جواب می‌گیرد، سؤال نیست.**

## اگر جواب خالی درآمد

۱. `MAX(Tarikh)` واقعی از `HadafForoshRoozanehNew`.
۲. فیلترها را یکی‌یکی بردار: بدون لاین چند سطر؟ بدون بازه چند؟ — تا معلوم
   شود کدام کشنده بود.
۳. پیشنهاد: «آخرین ماهِ موجود را بیاورم؟»

بیشترِ جواب‌های خالیِ این دامنه یکی از این دوتاست: **جدولِ مرده** یا
**بازه‌ی میلادی/شمسیِ جابه‌جا**.
