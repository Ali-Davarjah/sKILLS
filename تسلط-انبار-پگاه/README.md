# تسلط-انبار-پگاه

اسکیل تسلط بر اسکیمای `Warehouse` دیتابیس `PegahAI`، در فرمت استاندارد
`SKILL.md`. مستقل است: این پوشه را هرجا بگذاری کار می‌کند.

```
SKILL.md                      دستورالعمل — چیزی که مدل هر بار می‌خواند
schema.json                   نقشه‌ی ماشین‌خوان ۱۷۰ جدول (داده، نه کد)
scripts/map.py                پیمایش نقشه — table / refs / path / find / domain / external / crossref / traps / drift
references/entities.md        دامنه به دامنه
references/relationships.md   گراف اتصال، پل‌های بین‌اسکیمایی، تله‌ها
references/queries.md         کوئری‌های تأیید و الگوهای دامنه
references/reporting.md       شکل گزارش
examples/walkthrough.md       یک سؤال واقعی از اول تا آخر
```

## هفت تله که وقت زیادی می‌گیرند اگر از قبل ندانی

- **`Kala` دو شناسه دارد.** `ccKala` کلید جانشین، `ccKalaCode` کد کالا — و
  حدود ۲۵ جدولِ اقماری روی **دومی** کلید می‌خورند. ارجاع‌های `Sales` هم به
  همین می‌آیند (۶۸ ارجاع).
- **بچ دانه را ضرب می‌کند.** `COUNT(*)` روی `KardexSatr` تعدادِ کالا نیست،
  تعدادِ کالا×بچ است.
- **سه ستون تعداد و سه ستون قیمت** در `KardexSatr`. کدام مبناست، تصمیمِ
  کسب‌وکاری است نه فنی.
- **`MojodyForosh` عکسِ روزانه است.** برای «الان» آخرین `Tarikh` را بگیر؛
  جمعِ همه‌ی روزها موجودی را چند برابر می‌کند — **و عددش معقول به نظر
  می‌رسد**.
- **`Kardex.ccRefrence` چندریخت است** — بدون دانستنِ نوعش join نکن.
- **`Kala_14020830`** عکسِ کالا در ۱۴۰۲/۰۸/۳۰ است و ۵۴ ستون دارد — دقیقاً
  شبیه جدولِ اصلی.
- **`AmalkardRoozanehAnbar` / `AmalkardRozanehAnbar`** دوقلواند؛ یک `o` فرق.

`python scripts/map.py traps` تله‌های ساختاری را یک‌جا می‌دهد.

## اجرای مستقیم

```bash

python scripts/map.py path   Kala Kardex
python scripts/map.py find   Mojody
python scripts/map.py domain gozaresh
python scripts/map.py external

python scripts/map.py traps

```

پایتون ۳.۹ به بالا، بدون وابستگی بیرونی.

## جای این اسکیل در مجموعه

| سؤال | اسکیل |
|---|---|
| انبار، موجودی، کالا، بچ | **این** |
| فروش، فاکتور، هدف، تخفیف | `تسلط-فروش-پگاه` |
| پرسنل و حقوق | `منابع-انسانی-پگاه` |
| نمره‌ی فروشنده | `ارزیابی-فروشنده-پگاه` (**تست‌شده**) |
| درجه‌بندی مشتری | `رتبه-بندی-مشتریان-پگاه` (**تست‌شده**) |

این اسکیما **زیرِ پای فروش** است: `Sales.ccKalaCode` (۶۸ ارجاع) به
`Warehouse.Kala` می‌آید، یعنی هر تحلیلِ فروش که اطلاعات کالا بخواهد از اینجا
رد می‌شود. و اسکیل ارزیابی فروشنده برای معیارِ مرجوعی از
`Warehouse.ElatMarjoeeKala` استفاده می‌کند.

## نقشه از کجا آمده و چقدر قابل اعتماد است

- **جدول‌ها و ستون‌ها:** از فهرست کاملِ اشیای `PegahAI`. دقیق است.
- **۱۹۲ یال:** از قاعده‌ی `A.ccB → B` به‌علاوه‌ی قاعده‌ی کلیدِ دوم که
  `ccKalaCode` را به `Kala` می‌رساند. **هیچ‌کدام کلید خارجیِ اثبات‌شده
  نیست.**
- **۳۷ پل بین‌اسکیمایی:** مقصدشان در فهرست اشیای دیتابیس پیدا شده.
- **۲۷ نقشِ جدول:** از ساختار ستون‌ها نوشته شده؛ `ElatMarjoeeKala` از اسکیل
  **تست‌شده**ی ارزیابی فروشنده آمده.
- **کوئری‌ها:** الگو هستند و **اجرا نشده‌اند**.

نقشه از یک نسخه‌ی پشتیبان است. `map.py drift` تطبیق با دیتابیس زنده می‌دهد و
وقتی چیزی عوض نشده ساکت می‌ماند.

## پیوند با بقیه‌ی اسکیل‌ها

| مقصد | اسکیل | برای چه |
|---|---|---|
| `Global` (۱۹ جدول) | `تسلط-مشترک-پگاه` | مرکز پخش، افراد، گروه |
| `Sales` (۱۰) | `تسلط-فروش-پگاه` | مشتری، فروشنده، فاکتور |
| `HumanResource` (۲) | `منابع-انسانی-پگاه` | پرسنل و پست |

**در جهت عکس:** `Sales` یازده جدول اینجا را می‌خواند (`ccKalaCode` تنهایی
۶۸ ارجاع) و `Treasury` پنج تا — ولی این اسکیما هیچ‌چیز از خزانه نمی‌خواند.

از ۱۰۹ ارجاعِ بی‌جدول، ۵۳ تا نقش‌دارند. بزرگ‌ترینشان `ccMarkazAnbar` (۳۷)
که نامزدش `Global.Markaz` در نقشِ «انبار» است — **نامزد، نه کلید خارجی**.

نقشه‌ی کامل خانواده، ماتریسِ ارجاع و فهرستِ ارجاع‌های حل‌نشده در
[../SKILLS.md](../SKILLS.md). عددها را `crosslink.py` می‌سازد؛ دستی
به‌روزشان نکن.

## کارهای باقی‌مانده

۱. **سه ستون تعداد و سه ستون قیمت** — کوئری ۰.۲ و ۰.۳ تکلیف را روشن می‌کنند.
   تا آن موقع **هیچ گزارشِ مقداری یا ریالی قطعی نیست**.
۲. **کلید خارجی و تعداد سطر را بگیر** — با تعداد سطر می‌شود گفت کدام دوقلو
   زنده است.
۳. **آزمونِ یتیم** روی `ccKalaCode`، `ccAnbar`، `ccElat` — مخصوصاً `ccElat`
   که نامش کوتاه‌شده و اتصالش از بقیه حدسی‌تر است.
۴. **`ccMarkazAnbar`** با ۳۷ ارجاع در **هیچ** اسکیمای این دیتابیس جدول هم‌نام
   ندارد؛ مقصدش را پیدا کن.
۵. **دامنه‌ی SDPMS** (۴ جدول) ناشناخته است — چه سیستمی است و داده‌اش از کجا
   می‌آید.
